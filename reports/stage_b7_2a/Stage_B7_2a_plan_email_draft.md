Subject: Proposed B7.2a preregistration: O1/O2 proxy provenance decomposition

Dear Luke, Marcel, C.A.T., Thomas, Chris, all,

After B7.2, I think the next step should not be a new theory-facing module yet.

B7.2 drew a fairly sharp empirical boundary.

The current hierarchy is:

simple A/B history
-> beaten by true C

causal past-only A/B-derived operator estimator
-> beaten by true C

lag/horizon-separated O1/O2 summaries
-> beaten by true C

endpoint-adjacent O1/O2 operator proxy
-> not beaten by true C

So B7.2 does not support the claim that C is just A/B history.

But it also does not support the claim that C exceeds all A/B-derived operator information.

The bottleneck is now the endpoint-adjacent O1/O2 proxy itself.

The B7.2a question I propose is:

What is inside the O1/O2 proxy that C cannot beat?

More precisely:

Is the B7.2 endpoint-adjacent O1/O2 proxy genuinely just A/B-derived operator information, or does it already contain a compressed version of the phase-sensitive, non-substitutable, C-mediated structure that B6 detected?

B7.2a will therefore be an O1/O2 proxy provenance decomposition, not a C12 reconnection test.

The planned decomposition controls are:

1. o1_lag0_only
   Uses only O1_lag0_AB_raw.

2. o2_lag5_only
   Uses only O2_lag5_AB_raw.

3. o1_o2_joint
   Uses the joint endpoint-adjacent O1/O2 proxy.

4. phase_removed_o1o2
   Removes or marginalizes phase-bin structure from the O1/O2 proxy.

5. tfc_removed_o1o2
   Removes or marginalizes TFC-related structure from the O1/O2 proxy.

6. side_shuffled_o1o2
   Shuffles O1/O2 side/direction correspondence within session.

7. memory_only_o1o2
   Uses only past O1/O2 history, with endpoint-adjacent row information removed.

8. residual_endpoint_o1o2
   Uses residual endpoint-local O1/O2 information after removing past A/B, causal-estimator, and lagged-O1/O2 components.

The primary output will be a classification of the O1/O2 boundary:

- pure_ab_operator_proxy
- phase_sensitive_proxy
- tfc_compressed_proxy
- side_directional_proxy
- memory_proxy
- residual_endpoint_proxy
- compound_proxy

The interpretation rule is important.

If O1/O2 strength is explained by pure lag0/lag5 A/B operator information, then B7.2's boundary becomes stronger: C is above simple history, but below A/B-derived operator-proxy information.

But if O1/O2 strength depends on phase, TFC, side, direction, or residual endpoint-local structure, then B6 and B7 are not in conflict.

In that case, the structure seen in B6 may be compressed into the endpoint-adjacent O1/O2 proxy rather than absent from the system.

C12 remains paused in B7.2a.

B7.2a may motivate a later C12 reconnection test, but it will not use C12 to rescue or reinterpret the result.

I will preregister and execute this as B7.2a unless there are objections.
